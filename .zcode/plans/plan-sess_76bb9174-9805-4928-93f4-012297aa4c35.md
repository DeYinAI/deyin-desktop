# dsh-style repo restructure — capability-grouped packages, everything a plugin

**Goal:** Reshape deyin-desktop into DeepSeek-harness's layout: thin `apps/` shells that only bootstrap a kernel with a profile, and `packages/<group>/<pkg>/` capability groups where every capability (agent loop, tools, LLM adapters, commands, skills) is a plugin `{ name, inject, apply(ctx) }` behind a seam. Minimal zero-dep kernel of our own (~500–1000 LOC), no Cordis, no repo split. Dependency direction: `apps → plugin packages → kernel → extension-api`; nothing depends on a concrete provider.

## Target repo structure

```
apps/            desktop (Electron shell, --profile desktop) · web (host-server, --profile web)
                 · cli (TUI/headless, --profile cli|headless)   — bootstrap only, no feature code
packages/
  kernel/        extension-api (types, zero deps) · kernel (loader, lifecycle, config resolution,
                 scoped contexts, event bus, waterfall, isolation, lazy activation)
  core/          agent-loop (←agent-core/src/loop.ts) · session (→ append-only SessionEvent log)
                 · compaction · prompts
  llm/           llm (seam, ctx.llm) · llm-openai · llm-anthropic · llm-responses
                 (←agent-core/src/transports) · llm-catalog (←host-core DEFAULT_PROVIDERS)
  tools/         tools (seam: ToolRegistry as service) · tools-fs · tools-shell · tools-git
                 · tools-web · tools-plan · tools-agent (skill/task/memory)
  caps/          skill · commands · subagents · hooks · mcp  (directory-discovery → loader plugins)
  host/          fs · shell · pty · git   (←host-core host services; sandbox providers on web)
  guard/         ←agent-core PermissionEngine
  settings/      ←agent-core layered config
  storage/       ←host-core JSON storage + secret ciphers
  search/        ←host-core indexer/embedder
  openference/   oauth-client (←packages/oauth-client) · api (←host-core API clients)
  ui/            client (←apps/desktop/src/renderer) · contract (←apps/desktop/src/shared + web protocol)
  bundle/        base (core plugin rows) · desktop-app · web-app · headless
  plugins/       browser · security · visualize (←apps/desktop/bundled-plugins)
                 · optimization (←packages/optimization-plugin; kernel reference plugin)

vendor/          (reserved; we own our kernel)

```

Workspace globs become `packages/*`, `packages/*/*`, `native/*`. Package count 10 → ~35.

## Kernel API (extension-api)

```ts
interface PluginDefinition<C = unknown> {
  name: string;  inject?: string[];  activateOn?: ActivationEvent[];
  apply(ctx: PluginContext, config: C): void | Promise<void>;
}
interface PluginContext {
  get<T>(key: ServiceKey<T>): T;  provide<T>(key, factory): void;
  on(event, cb): Unsubscribe;  emit(event, payload): void;
  waterfall<T>(event, seed: T): Promise<T>;  effect(cleanup): void;  logger;
}
```
Seams on ctx: `llm, tools, commands, skills, subagents, hooks, mcp, shell, fs, pty, permissions, sessions`.

## Composition, trust, isolation

- Plugin rows `- { id, plugin, config, enabled }` resolved in layers: `bundle-base` → profile patch (`desktop|web|cli|headless`) → user patch (`~/.deyin/plugins.yaml`) → workspace patch (`.deyin/`, trust-gated as today) → CLI overlay. `--dump-config` prints the resolved tree.
- In-process plugins = first-party/bundled + GitHub-installed via existing PluginService gating; per-plugin failure isolation (load error → plugin marked failed, shown in Plugins settings, host continues). Untrusted code stays out-of-process behind MCP.

## Migration phases (each ends with verify.sh green)

**Phase 0 — Decouple & clean:** remove committed build artifacts (`apps/desktop/release/`, `out/`) from git; extract `packages/ui/contract` and `packages/ui/client`; delete web's `@renderer/*`/`@contract/*` aliases; fix stale PARITY.md rows.

**Phase 1 — Kernel lands:** create `kernel/extension-api` + `kernel/kernel` with tsx --test suites (inject ordering, dispose, scoped ctx, waterfall, isolation, lazy activation); migrate optimization-plugin onto the kernel (replaces `bindAgentCacheHooks` in desktop `agent.ts`).

**Phase 2 — Physical restructure + seams (strangler):** move folders to the target tree above (`git mv`, update workspace globs, fix imports); `ctx.tools` — registration moves from `createBuiltinRegistry()` to tool-family plugins, implementations stay put; `ctx.llm` — transports become adapters keyed by `apiFormat`, catalog seeding into `llm-catalog`; `caps-local` loader plugin wraps `scanCapabilities()`; desktop `agent.ts:445-469` manual wiring becomes plugin rows in `bundle/desktop-app`.

**Phase 3 — Config-layer composition:** implement rows/profiles/patches + `--dump-config`; define `bundle/base` + per-app bundles.

**Phase 4 — Lazy activation & web parity:** `activateOn` across families (PTY, MCP, embeddings, indexer on first use); Plugins page shows failed/disabled state; plugins/caps load inside the web session sandbox (currently desktop-only).

**Phase 5 — Session event log spine:** append-only `SessionEvent` log; transcript/fork/replay derive from it; guarded by existing migration + e2e suites.

## Testing & docs

All 73 existing test files + agent-core e2e/load suites stay green at every phase; new packages follow the repo `tsx --test` pattern; config resolution gets golden tests. ARCHITECTURE.md gets the extension-model diagram (IDE Core → extension API → plugins → skills/tools/commands/MCP) plus a plugin-authoring cookbook.

## Risks

Renderer extraction is the riskiest mechanical step → done alone in Phase 0, verified on both runtimes. Tool-split drift → move registration, not implementation. Session log is a data migration → last. Granularity (~35 pkgs) is deliberate (dsh runs ~90+); pnpm + tsc per package scales, root scripts unchanged (`pnpm -r`).

Later option value: publish `extension-api`/`ui`/`contract` as versioned npm packages so external plugin repos can depend on them — ecosystem without repo split.
